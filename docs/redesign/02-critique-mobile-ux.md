# 진단: "모바일게임답지 않다"의 실체

결론부터: 이 게임의 UI는 **"프로토타입 디버그 UI가 그대로 출시 직전까지 온 상태"**다. 게임 시스템·연출(셰이크/플래시/햅틱)은 상용급인데, 그 위에 얹힌 조작면(chrome)이 개발자 도구 미학이라 부조화가 불만의 정체다. 관점별로 쪼갠다.

---

## 1. 비주얼 아이덴티티 — 심각도: 치명

**근거**: 버튼 ~45개 전원이 `Phaser Text + backgroundColor` 단색 사각형, 폰트는 전부 시스템 monospace 단일, 아이콘 이미지 에셋 0개, 이모지 사용처 60+곳, 재화조차 💎💀 이모지. HUD 라벨은 "Gem:", "Gold:", "Units:" 영문 텍스트.

**진단**: monospace는 유저 눈에 "터미널/코딩 화면"으로 읽힌다. 랜덤다이스·러시로얄·쿠키런의 버튼은 예외 없이 ①라운드 코너 ②상하 그라디언트+하이라이트 ③1~2px 아웃라인 ④드롭섀도 ⑤전용 아이콘의 5요소를 갖춘 "캔디 버튼"이고, 재화는 반짝이는 코인/젬 스프라이트다. 이모지는 OS마다 렌더가 달라(안드로이드 기종별 👾 모양이 다름) 브랜드 통제가 불가능하고, "무료 웹게임" 신호를 강하게 낸다. 아이러니하게 artnouveau.ts 벡터 패널(금테+덩굴)과 NovelAI 유닛 18종은 이미 고급 아이덴티티를 갖고 있다 — **문제는 에셋 부재가 아니라 '유닛은 아르누보, 버튼은 메모장'인 이중 언어**다.

**방향**: 나인패치 버튼 3종(주/보조/위험)+한글 지원 게임폰트(예: 넥슨Lv2고딕급 무료폰트) 도입만으로 절반 해결. 재화 아이콘 2종(젬/영혼)과 적 스프라이트를 아르누보 톤으로 통일. 이모지는 토스트 같은 휘발 텍스트에만 잔류 허용.

## 2. 터치 인체공학 — 심각도: 치명

**근거**: ⏸/📖 버튼 실측 **27×19px**, 속도 버튼 25×19px, 소환 버튼 높이 ~26px. 360px 폭 기준 1px≈1pt이므로 Apple 44pt/Google 48dp 최소 규칙의 **절반 이하**. 게다가 ⏸(154,68)·📖(206,68)·2×(244,68)는 화면 상단 — 세로 한손 그립에서 엄지가 닿지 않는 사각지대다. 모든 버튼이 `pointerdown` 즉발이라 미스터치=즉시 발동(일시정지 오발 등). 판매존은 표시(322,568)와 판정(x≥290, y≥548)이 불일치.

**진단**: "한손 세로 플레이"가 타깃인데 조작 요소가 상·하단에 분산돼 있고, 상단 것들은 두 손 그립을 강요한다. 상용 게임은 액션 버튼을 전부 하단 1/3에 몰고, 상단은 순수 표시 전용으로 비운다.

**방향**: ①⏸·📖·배속을 하단 바로 이관하거나 최소 44×44 히트영역(비주얼보다 큰 투명 히트박스) 부여 ②파괴적이지 않은 버튼도 `pointerup + 영역 내 확인`으로 전환 ③소환 버튼을 러시로얄처럼 하단 중앙 대형(64px+) 버튼으로 승격 — 판당 수십 번 누르는 최다 빈도 입력이다.

## 3. 정보 계층 — 심각도: 높음

**근거**: 타이머 20px, 골드 16px, 적 카운트 18px, 유닛 수 16px — 전부 14~20px 대역에 몰려 있고 상단 바에 6개 정보가 균등 나열. 골드는 판당 수십 번 참조하는 **의사결정 화폐**인데 좌하단 구석 16px.

**진단**: 위계가 평평하면 유저는 매번 스캔 비용을 치른다. 이 게임의 순간 판단은 "소환할 골드가 되나 → 적이 몇 마리나 쌓였나" 두 개다. 골드는 소환 버튼과 물리적으로 붙어 대형 표시돼야 하고(랜덤다이스가 SP를 소환 버튼 안에 넣는 이유), 적 카운트는 40 임박 시에만 커지는 동적 위계가 필요하다. 타이머는 생존 게임이므로 중상단 대형 유지가 맞다.

**방향**: 골드를 소환 버튼 내부/직상단에 코인 아이콘+굵은 숫자로 통합. 적 게이지는 4px 실선 대신 상단 전폭 게이지로 승격, 60%/80%에서 두께·발광 증가. "Units n/m"은 평시 축소.

## 4. 주스(Juice) — 심각도: 높음

**근거**: 버튼 프레스 피드백이 hover 색 변경뿐(모바일에서 hover는 존재하지 않음 = **사실상 무피드백**). 골드/젬 숫자 롤링 없음, 처치→골드가 코인으로 날아와 잔고에 박히는 연출 없음, 씬 전환은 타이틀 300ms 페이드 1개, 팝업 등장/퇴장 트윈 없음(즉시 출현), 승리 💎+1도 텍스트 한 줄.

**진단**: 전투 주스(셰이크·플래시·프리즈·햅틱)는 이미 상위권인데 **UI 주스가 0**이라 낙차가 크다. 모바일 유저가 "게임답다"를 느끼는 최소 문법: 누르면 0.95배 스케일 다운→복원, 획득 재화는 발생지→HUD로 비행, 숫자는 카운트업, 팝업은 스케일 0.8→1.0 back-ease 등장.

**방향**: 공용 `JuicyButton` 래퍼 1개(스케일 트윈+SFX 틱)로 45개 버튼 일괄 해결 — 공수 대비 체감 최대 항목. 골드 비행 파티클, 잔고 롤링, 팝업 등장 트윈 순으로 추가.

## 5. 온보딩/FTUE — 심각도: 치명

**근거**: 튜토리얼 = 검정 0.88 덮개 + **14px 텍스트 19줄** 단일 블록, 탭으로 해제. 이후 W1 힌트 토스트뿐.

**진단**: 상용 게임 FTUE는 "읽기"가 아니라 "하기"다: 화면 딤+타깃만 스포트라이트→핑거 포인터가 드래그 경로 시연→유저가 실제 수행해야 진행→즉시 보상. 19줄 텍스트는 대부분 읽지 않고 탭해 넘기며, 이 게임의 킬러 기믹(드래그로 겹쳐 교배)은 텍스트로 전달이 가장 안 되는 조작이다. W1의 단계별 기능 해금 설계는 이미 훌륭하므로 뼈대는 있다.

**방향**: W1-1에서 강제 인터랙션 4단계(소환 탭→유닛 드래그→교배 겹치기→합성)로 교체. 손가락 스프라이트 1장+트윈이면 구현 가능. 텍스트는 단계당 1줄.

## 6. 레이아웃 관례 — 심각도: 높음

**근거**: 타이틀은 탭 유도 텍스트만(설정/로고 없음), 스테이지 선택 하단에 영구강화 6행이 텍스트로 나열(구매 시 scene.restart로 화면 전체 리빌드 — 깜빡임), RecipeBook은 11px 25줄 고정 한 화면(스크롤 없음), 로비 개념 부재.

**진단**: 랜덤다이스류의 화면 문법은 "하단 탭바 로비(상점/덱/전투/도감) + 전투 화면은 하단 소환 대형 버튼 + 상단 미니 정보"다. 현재는 로비가 없어 메타(강화·도감·상점)가 스테이지 선택 화면 하단과 인게임 팝업에 파편화됐고, 이는 메타 분석 보고의 "판 사이 루프가 감정적으로 닫히지 않는다"와 같은 뿌리다. 11px/9px 텍스트는 모바일 최소 가독선(12sp) 미달.

**방향**: 당장 로비 신설까지 안 가도 ①스테이지선택을 "월드맵(상) / 하단 탭: 출격·강화·도감" 구조로 재편 ②강화 구매는 restart 대신 해당 행만 갱신+구매 연출 ③레시피북 스크롤 컨테이너화+최소 12px.
