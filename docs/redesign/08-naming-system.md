> 2026-07-06 확정. v3 기획서 R4·R4b의 미확정 데이터(계열명·매핑·혈통명 규칙)를 여기서 확정한다.
> 구현 대상: `src/game/naming.ts` (신규, 순수 TS — Phaser 의존 0). 하위 모델은 이 문서의 상수를 그대로 옮기면 된다.

## 1. 계열 확정 — 3문(門)

콘셉트: "명가(名家)" 세계관 — 가문은 셋 중 하나의 **문(門)** 에 속한다. 알 문장(AM1)·문장 오버레이(Graphics)와 1:1 대응.

| FamilyKey | 계열명 | 소속 T1 | 상징 문장 (AM1 알과 동일) | 색 (기존 Race 색 유지) |
|---|---|---|---|---|
| `sword` | **검문(劍門)** | Warrior, Archer | 검+방패 | `#4488ff` |
| `fang` | **야수문(牙門)** | Dog, Squirrel | 발톱+잎사귀 | `#44cc44` |
| `steel` | **강철문(鋼門)** | Android, Cannon | 톱니+회로 | `#aa44cc` |

```ts
export type FamilyKey = 'sword' | 'fang' | 'steel';
export const FAMILY_OF_RACE: Record<Tier1Race, FamilyKey> = {
  Warrior: 'sword', Archer: 'sword',
  Dog: 'fang', Squirrel: 'fang',
  Android: 'steel', Cannon: 'steel',
};
export const FAMILY_LABEL: Record<FamilyKey, string> = { sword: '검문', fang: '야수문', steel: '강철문' };
```

> 기존 `Race`(Human/Beast/Robot) 타입은 교배 가능 판정용으로 그대로 두고, `FamilyKey`는 별도 상수로 추가한다 (기존 코드 무접촉).

## 2. 혈통명 생성 규칙

**생성 시점:** Gen0 부모 2마리에서 **Gen1 자식이 태어나는 순간 = 가문 창설**. 혈통명 1회 생성, 이후 그 계보의 모든 자식·융합 결과물이 승계. (Gen 유지 이계열 교배도 부모 중 최대 Gen 쪽 혈통을 승계, 둘 다 Gen0이면 신규 창설.)

**형식:** `접두(수식) + 접미(계열 명사)` — 붙여쓰기, 공백 없음. 예: **은빛칼날**, **서리송곳니**, **황혼태엽**.

- 접미는 **자식의 계열** 풀에서 뽑는다 (동계열 교배면 부모 계열, 이계열이면 자식 종의 계열).
- 길이 상한: 접두+접미 합계 **7자 이하** (바텀시트·계보 카드 320px 폭 기준). 아래 풀은 전부 조합해도 7자 이내.
- 표시 형식: 가문 등록부·혈통서 = `은빛칼날 가(家)` / 유닛 개체 = `은빛칼날 N세` (Gen1=시조, Gen2=2세 … Gen4=4세) / 융합 결과물 = `은빛칼날의 Astral God`.

### 생성 함수 사양

```ts
export function generateBloodlineName(
  family: FamilyKey,
  rng: () => number,          // GameState의 기존 의사난수 재사용 (Math.random 금지 — 시뮬 재현성)
  used: Set<string>,          // 현재 판 + 등록 가문 이름 전부
): string
```

- `prefix[floor(rng()*36)] + suffix[floor(rng()*12)]`, `used` 충돌 시 재롤 최대 8회 → 그래도 충돌이면 `이름II`, `이름III` … 로마숫자 접미 (중복 대가문 서사로 수용).
- 순수 함수 — 10만회 시뮬에서 호출돼도 부작용 없음. 유닛 테스트: 충돌 8회 초과 시나리오, 7자 상한 전수 검사.

## 3. 변이 칭호 (이름 앞 붙는 수식, 렌더 전용)

| 등급 | 칭호 | 표시 |
|---|---|---|
| 일반 변이 | 없음 (도감 기록 + +10G만) | — |
| **희귀** | `벼락맞은` `축복받은` `각성한` `달을삼킨` `두번태어난` `운명의` 중 rng 1개, 개체에 저장 | 이름 앞 은색 — "벼락맞은 서리송곳니 2세" |
| **전설** | `신탁의` `태초의` `왕을낳은` `별의계승자` `신을엿본` `문을연` 중 rng 1개 | 이름 전체 **금색** (v3 R6 '금빛 이름') |

```ts
export const EPITHET_RARE: string[]   = ['벼락맞은', '축복받은', '각성한', '달을삼킨', '두번태어난', '운명의'];
export const EPITHET_LEGEND: string[] = ['신탁의', '태초의', '왕을낳은', '별의계승자', '신을엿본', '문을연'];
```

- 칭호는 **개체 필드** (`UnitData.epithet?: string`), 혈통명과 별개 — 계보 체인에서 "어느 세대에서 변이가 터졌는지" 읽히는 장치.
- 칭호+이름+세대 최장 표기: "별의계승자 눈보라용광로 4세" = 13자 → 바텀시트 폰트 14px 기준 1행 수용 확인(320px). 카드에서는 칭호를 윗줄 분리 표기.

## 4. 데이터 저장 사양

```ts
// UnitData 확장 (M3)
lineageId?: number;      // 판 내 혈통 일련번호
bloodlineName?: string;  // 생성된 문자열 그대로 저장 (시드 재생성 방식 금지 — 풀 개편 시 이름 변형 방지)
epithet?: string;

// 계보 체인 노드 (MetaProgress 가문 등록용, 노드 ≤8)
export interface PedigreeNode {
  race: UnitRace; gen: number; name: string; epithet?: string;
  mutation?: 'common' | 'rare' | 'legend';
}
```

- 이름은 **문자열 그대로 직렬화** — localStorage 부담 없음(노드당 ~40byte × 8 × 슬롯 상한).
- 영문 로컬라이즈는 출시 후 과제 — 풀 구조가 접두/접미 분리라 번역 테이블 교체만으로 대응 가능. 지금은 한국어 고정.
