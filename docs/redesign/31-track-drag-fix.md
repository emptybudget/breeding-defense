# 트랙 비주얼 + 드래그 원위치 문제 — 진단·구현 스펙 (하위 모델 킥오프)

> 2026-07-09, Fable 진단. 사용자 증상: "유닛을 옮길 때 원위치로 돌아오는 게 많다. 오류라기보단 맵 비주얼 문제 같다. 제일 거슬리는 요소는 바닥 트랙." → **정확한 직감**: 크래시성 버그는 없고, ①보이지 않는 금지 영역 ②말없는 원위치 폴백 ③밋밋한 트랙 렌더가 겹친 설계 문제다.
> 대상 모델: Sonnet/Opus 구현 세션. 이 문서만 읽고 착수 가능하도록 수정 지점을 file:line까지 명시. **모바일 성능 무영향이 절대 조건** (전부 1회 드로우/판정 상수 수준 — 프레임 비용 증가 0이어야 함).

## 1. 수정 스펙 (F1~F4, 이 순서대로)

### F1. 트랙 리비주얼 — `GameScene.ts:119-127` 교체
현재 단일 `lineStyle(36, 0x2a2818)` 스트로크를 **3층 1회 드로우**로:

```
strokeLoop(width, color):            // 헬퍼 — 폐루프 스트로크 + 각 웨이포인트에 fillCircle(width/2)로 모서리 라운딩
  1층 테두리: strokeLoop(42, 0x1a1810)   // 배경(#0d0c08)보다 살짝 밝은 음각 테두리
  2층 본체:   strokeLoop(34, 0x2a2818)   // 기존 톤 유지 (팔레트 변경 아님)
  3층 중앙 진행 점선: lineStyle(2, 0x554d2a, 0.55) — 각 세그먼트를 따라 20px 간격, 8px 길이 대시
```

- 전부 `create()` 1회 드로우 Graphics — 프레임 비용 0 (모바일 조건 충족).
- 모서리 라운딩은 `fillCircle`(웨이포인트마다 반지름 width/2)이 마이터 각짐을 덮는 방식 — 별도 조인 설정 불필요.
- **금색 금지**(헌법 4조 — 금색은 혈통 독점). 점선은 적 경로 가독용이지 장식이 아님.

### F2. 판정 반폭 22 → 18 — `GameState.ts:231-240`
- `_onTrack`의 `< 22`를 `< 18`로. 주석도 갱신: "반폭 18 = 렌더 본체(34px)+테두리(42px) 안쪽 — 판정 폭(36)이 비주얼(42)보다 항상 좁아서, 거절은 반드시 눈에 보이는 트랙 위에서만 일어난다."
- 근거(헌법 3조 — 상수 1개, 기하 실측): 기존 22는 비주얼 반폭 18보다 4px 넓은 보이지 않는 금지 띠(C1). F1의 42px 테두리와 함께 **judged(36) ⊂ visual(42)** 관계가 성립해야 함.
- 부수 효과: 소환 위치 산란(`GameState.ts:547,737`)도 같은 판정을 쓰므로 트랙에 4px 더 가깝게 스폰 가능 — 의도된 완화, 별도 조치 불요.

### F3. 드롭 관용화 — `DragController.handleDrop` 재구성 (핵심)
원칙: **"이유 없는 원위치"를 없앤다.** 원위치는 ①독 영역 미스(M1b 스펙의 의도된 취소) ②구제 실패(드묾)+토스트, 두 경우만.

```
handleDrop 꼬리 재구성 (판매존·둥지 분기까지는 현행 유지):
  vacateNestSlot(prevSlot)
  targetId = 35px 최근접 유닛 (둥지 대기 제외 — 현행 유지)

  ① targetId 있으면 tryUnitInteraction(dropped, targetId):
     - synthesize 피처 off / 상대·자신 breeding / 어느 쪽이든 잠금 / T4 포함 / 티어 불일치 → false
     - 동티어(1·2·3)면 trySynthesize 호출(기존 showEffect·cleanupStale 시맨틱 그대로:
       T3=cleanupStale true, T1=showEffect false) — **합성이 실제 성립했을 때만 true**
     - true면 드롭 종료(스프라이트 정리는 trySynthesize가 이미 함), false면 ②로 폴스루
  ② 이동 처리 — fieldDrop = (go.y < DOCK_Y) 를 먼저 캡처:
     - fieldDrop이면: 존 클램프 → isClearPos 검사 → 실패 시 findClearPos 구제 → 배치
       · 클램프: x∈[z.x1,z.x2], y∈[z.y1, min(z.y2, DOCK_Y)]
       · isClearPos(x,y,selfId) = isValidUnitPosition && !isOnTrack && 다른 유닛 28px 이내 없음
         (28 < 35라 기존 '빈 공간' 드롭은 항상 통과 — 회귀 없음. 유닛 겹쳐 쌓임 방지용)
       · findClearPos는 isClearPos를 쓰도록 시그니처에 selfId 추가 (기존: 존+트랙만 검사)
     - 배치 성공: moveUnit + go.setPosition + rangeCircle 동기화 (기존 이동 코드 재사용)
  ③ 최후 폴백: 원위치 + fieldDrop일 때만 토스트 '⚠️ 놓을 빈 자리가 없음'
     (독 영역 미스는 토스트 없이 조용히 원위치 — M1b '존 밖 드롭=취소' 스펙 보존)
```

- `trySynthesize` 반환형 void → boolean (`result` 유무). 실패 시 `pendingNotification` 토스트는 현행 유지 — "조합법이 존재하지 않습니다" 후 유닛이 옆에 놓이는 게 새 정상 동작.
- FTUE F8 완료 경로(`trySynthesize` 내부)·둥지 점유 제외·잠금 유닛의 '이동은 허용' 현행 유지.
- **바뀌는 체감**: 유닛 옆에 놓기·트랙 근처 놓기·존 살짝 밖 놓기가 전부 "가까운 빈 자리로 스르륵 놓임"이 된다. 원위치가 나오면 반드시 이유가 보인다(독 취소 or 토스트).

### F4. 둥지 드래그 실패 문구 — `DragController.ts:326`
- `'⚠️ 같은 카테고리 유닛만 교배 가능'` 고정 문구는 오정보(이계열 교배가 정식 루프고, 실제 거절 사유는 대부분 예산 소진). `sendToNest`(DragController.ts:346-350)와 동일 분기 재사용: 예산 소진이면 `'⚠️ 이번 판 교배 예산 소진 (6회)'`, 아니면 `'⚠️ 교배 불가 (잠금/교배중 유닛)'`.

## 2. 완료 판정 게이트

1. `npx tsc --noEmit` 통과 (**npm run build 실행 금지** — 사용자가 직접).
2. 기존 순수 테스트 회귀 없음 — 이 환경에서 vitest 기동 불가 시 M4 방식(esbuild 번들→node 실증) 재사용. `_onTrack` 반폭 18 케이스 테스트 1건 추가(경계 17.9/18.1).
3. 사용자 플레이 게이트: **필드 재배치 10회 연속 시도에서 '이유 모를 원위치' 0회** + 트랙 경계가 눈으로 구분됨 + 5개 트랙 레이아웃 전부에서 확인(레이아웃은 판마다 랜덤 — 새 판 5회).
4. 모바일 조건: 신규 per-frame 로직 0 (F1은 create 1회, F2는 상수, F3은 드롭 이벤트 시에만) — 코드 리뷰로 확인.

## 3. 건드리지 말 것

- `DRAG_LIFT_OFFSET_Y`(-40)·`DRAG_SNAP_DIST`(40)·둥지 스냅/미리보기/확정 흐름 (M4 완성분).
- `computeUnitZone`의 고정 사각형 — F3 클램프가 UX를 해결하므로 존 자체 확장은 하지 않는다(존 확장은 배치 가능 면적=밸런스 변경이라 별도 시뮬 필요, 이번 범위 밖).
- 판매존/독 기하(`dockGeometry.ts`), 트랙 웨이포인트 5종 레이아웃·지터.
- 트랙 팔레트 대체(아트 교체는 AM 트랙으로 — 이번엔 Graphics 3층까지만).
