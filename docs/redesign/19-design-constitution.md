# 디자인 헌법 — 미래 결정 심사 기준

> 2026-07-06 제정. 목적: 상위 모델 없이도 새 아이디어·피드백·밸런스 논쟁을 **일관되게 심사**하기 위한 규칙. 이 문서는 "무엇을 만들까"가 아니라 **"어떻게 결정할까"** 를 남긴다.
> 개정: 사용자만 가능. AI는 이 헌법과 충돌하는 작업 요청을 받으면 충돌을 고지하고 진행 여부를 물어라.

## 제1조 — 코어 판타지 적합성 테스트 (신규 아이디어 3문항)

모든 신규 시스템/콘텐츠 제안은 채택 전에 다음을 통과해야 한다:

1. **박자 문항**: 4박자(Plan/Grind/Pop/Loop) 중 어느 박자를 강화하는가? 어느 박자도 못 대면 기각. 현재 최약 박자(측정: 최근 플레이테스트)를 강화하는 제안이 우선.
2. **혈통 문항**: "낳는 게임" 정체성을 강화하는가, 희석하는가? 교배·혈통·계보와 무관한 "뽑기류" 시스템은 원칙 기각 (11번 BM 원칙 1과 동일).
3. **7분 문항**: 한 판 7분의 기승전결 안에서 작동하는가? 세션을 늘리거나 판 밖 대기를 만드는 제안(에너지·건설 타이머류)은 기각.

## 제2조 — 더하기 전에 빼기

- 새 시스템 1개 추가 제안 시, **뺄 것 1개를 함께 제시**해야 한다 (v3 §빼는 결정 22건의 전통). 뺄 게 없다는 건 게임을 아직 충분히 이해 못 했다는 신호.
- 신규 유저 첫 15분에 노출되는 개념 수는 **현행(소환·교배·합성·라운드) + Gen** 이 상한. 이 구간에 개념을 추가하는 제안은 다른 개념의 W2 이연과 맞교환.

## 제3조 — 밸런스 변경 프로토콜

1. **감으로 바꾸지 않는다.** 수치 변경은 ①시뮬(12번 방법론: `docs/redesign/balance_sim.py` 스타일 몬테카를로 또는 `tests/`의 TS 시뮬) ②플레이테스트 실측 중 최소 1개 근거 필수.
2. **상수는 한 번에 1개.** 두 개 이상 동시 변경 시 원인 귀속 불가. 변경→게이트 재측정→기록→다음 상수.
3. 변경 근거·결과를 12번 문서의 표에 **추가 기록** (덮어쓰지 말 것 — 이력이 자산).
4. 확률형(변이·피티) 변경은 시뮬 10만회 ±3σ 재검증 없이 머지 금지.

## 제4조 — 감각 위계 (연출·사운드 불변 규칙)

1. **금색 = 혈통 독점.** 다른 시스템이 금색을 쓰기 시작하면 잭팟이 죽는다 (T2 잭팟=백금 유지).
2. **낙차 보존**: 결과가 나오기 전에 등급을 스포일하는 연출 금지 (알은 계열만, 부화 사운드 앞 0.15s 동일 — 10번 원칙).
3. **연출 위계 고정**: 인게임 전설 변이 > 부화당(BM) > 기타. 돈 낸 순간이 게임 순간보다 화려해지면 안 된다.
4. **볼륨·화면 점유 상한**: 새 연출은 E14 배너 우선순위 표에 편입돼야 하며, 최상위(보스 컷인)보다 길거나 클 수 없다.

## 제5조 — 스코프 방어 (1인 개발 지속 가능성)

1. 마일스톤 중간에 발견한 "좋은 아이디어"는 구현하지 않는다 — **PROGRESS의 후보 표에 적고 지나간다.**
2. 신규 어셋이 필요한 제안은 장수를 명기해야 한다. NovelAI 10장 초과 요구 = 자동으로 다음 버전행.
3. "리팩토링하면서 겸사겸사"는 금지 — 리팩토링은 refactor-expert 에이전트로 별도 세션, 동작 보존 + `npm test` 통과가 조건.
4. 외부 SDK/신기술 도입(광고·분석·엔진 교체)은 Capacitor 패키징(BM2) 전까지 동결.

## 제6조 — 검증 없이는 완료 없음

1. 모든 작업의 완료 선언은 `npm run build && npm test` 통과가 최소 조건. 테스트가 없는 신규 순수 로직은 테스트를 함께 내야 완료.
2. 플레이테스트 게이트는 건너뛸 수 없다. 게이트 실패 시 20번 플레이북 → 그래도 2회 연속 실패면 해당 기능을 **빼는 것**을 1순위 검토 (제2조).
3. 유저 피드백은 "증상"으로 취급 — 유저가 제안한 해법을 그대로 구현하지 말고, 어떤 박자가 아픈지 진단부터 (예: "업그레이드 넣어줘" → 실제 문제는 Grind 공허였음, U14 사례).

## 제7조 — 결정의 기록

- 채택이든 기각이든 **한 줄 사유와 함께 PROGRESS 또는 해당 redesign 문서에 기록**한다. 기각 이력이 없으면 같은 아이디어가 세션마다 부활한다 (이미 기각: 종족선택 소환, 오버킬 연쇄, 4티어 각성 궁극기, 합성 미리보기 고스트, 에너지 시스템, 캐릭터 뽑기, 💎 유료 판매, v3 §빼는 결정 22건).
- 문서 간 충돌 발견 시: 05(v3) > 12~17(전문 문서가 명시 수정한 부분) > 01~04(이력) 순으로 우선하되, 충돌 자체를 발견 즉시 문서에 각주로 남긴다.

## 부칙 — "Fable이라면 뭐라 했을까" 속기 체크리스트

새 제안을 받았을 때 30초 심사:
- [ ] 어느 박자? (1조) / 낳는 게임에 +인가? (1조) / 7분 안인가? (1조)
- [ ] 뭘 뺄 건데? (2조) / 첫 15분 개념 수 초과? (2조)
- [ ] 수치면 시뮬 근거는? (3조) / 금색·낙차·위계 침범? (4조)
- [ ] 어셋 몇 장? 스코프 몇 M? (5조) / 기각 이력에 있나? (7조)
- 전부 통과 → PROGRESS 후보 표에 등록하고 우선순위 배정. 하나라도 걸림 → 사유와 함께 기각 기록.
