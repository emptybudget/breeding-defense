# 출시 마일스톤 스파인 — M6~M10b (G/S/V/L 4계열 통합 재배열)

> 2026-07-16 제정 (Fable 5, 코드 무변경). **사용자 확정 2건**: ①출시 전개 = **볼륨 완성 후 출시**(30번 기조 그대로 — 모바일 소프트런칭 선행안 기각) ②본 체인 공식 채택.
> 성격: 신규 기획이 아니라 **재배열** — 21번(G1~G5)·29번(S-A~H)·30번(V1~V5)·23번(L1~L6)이 각자 문서에 떠 있던 것을 M1a~M5와 같은 문법(자기완결 스코프+완료 판정+플레이 게이트+담당 모델)의 단일 체인으로 통합. 30번 §6이 숙제로 남긴 "우선순위 재배열"의 정식 답.
> ⚠️ 21번 투입 순서표(M5 직후 G4)는 "모바일 출시 완료" 전제였음 — 볼륨 선행 전략 확정으로 **본 문서가 M5 이후 순서의 유일 원천**(21번 §투입 순서는 폐기, 채점표 자체는 유효).

## 0. 대전제

- **플랫폼 중립 콘텐츠(M6~M9) 먼저 → 패키징(M10a/b) 마지막.** M6~M9 산출물은 모바일/Steam 어느 빌드에도 그대로 실린다 — 출시 형태 결정이 늦어져도 손실 0.
- **어느 마일스톤에서 멈춰도 그 시점 빌드가 출시 가능 단위** (M1a~M5 체인과 같은 안전 설계). 역할 분담: M6~M7 = "혼자서도 재밌는 게임"(오프라인 완결) / M8 = "매일 켤 이유" / M9 = "파고들 이유" / M10 = "팔 수 있는 형태".
- 헌법(19번) 그대로 적용: 각 M 착수 = 킥오프 블록 작성(18번 방식), 밸런스 상수 1개씩, 신규 기획은 3문항 심사.

## 1. 설계 원칙 3

1. **인프라 1회 구축 = 콘텐츠 3회 소비** — Firebase 익명 인증을 한 번 세우면 클라우드 세이브(G5)·주간 리더보드(G1)·일일 런(V5)이 전부 위에 얹힘 → 셋은 반드시 M8 한 묶음.
2. **사용자 병렬 트랙 분리** — BGM 생성·NovelAI·번역은 코드 마일스톤과 독립(§4). 마일스톤이 사용자 자산을 기다리며 멈추지 않게 "필요 시점"만 못 박는다.
3. **시뮬 게이트 우선** — 밸런스가 걸린 M6은 몬테카를로 시뮬(12번 체계) 통과가 플레이 게이트보다 선행.

## 5. v1.1+ 인계 — 23번 캘린더 조정분

L1(유파)이 M9로 **선반영**됨 → 23번 연간 캘린더의 분기1 슬롯은 **L6 시즌틀 구축**으로 대체. 이후 그대로: 분기2 L3(Ruin_God 강림+진영, 27번) → 분기3 L2(가문 전당 — **영구 💀 획득 경로 설계 선행**, M5에서 이월된 가문 시드·2차 트리 여기서 해소) 또는 L4(침공, 지표 보고 택1) → 분기4 L5(월드 4)+대제전. 복귀 캠페인은 대형 축 출시와 항상 동시 집행(23-§2).
